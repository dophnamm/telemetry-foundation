Read this left to right along the time line. Every service always logs at DEBUG, and the agent on each node keeps exactly the last 15 minutes, stored per service and per minute, capped at 2 GiB per node and shared fairly so one noisy service cannot shrink everyone else's window. Anything older is deleted automatically. When a service logs a FATAL error or its errors spike, marked in red, the agent waits ten seconds to capture what happens right after, then freezes the window into a snapshot kept for 24 hours. The snapshot uses hard links, so nothing is copied twice. A support package created later, even an hour after the incident, still contains the debug context from before it. It is pulled through an authenticated API and personal data is masked before it leaves the site. Other vendors ask customers to turn on debug and wait for the failure to happen again; we skip that round trip.
