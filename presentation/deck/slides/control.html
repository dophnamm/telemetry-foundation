Top row, log-level control: an admin sets the level per service, and optionally per logger and with an expiry, through the API, CLI or UI. That writes one configuration that the agent on every node watches, so the new level applies in under ten seconds with no restart. Because the recorder always keeps DEBUG locally, the level only decides what reaches the central log store that customers search. Bottom row, OCSF events: platform services emit audit and file-processing events in the OCSF format. They travel on their own durable queue, are never filtered or sampled, and the gateway delivers them to the customer's SIEM, whether Splunk, Kafka, S3 or syslog. The two rows connect: every log-level change is itself an audit event. Every event carries a sequence number, so a gap at the destination raises an alert instead of a silent loss. We author against OCSF 1.9.0 but commit to fields compatible with OCSF 1.3, which is what SIEMs read today.
