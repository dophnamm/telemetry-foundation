This is the one design decision everything else follows from. On the left, option B: every language's SDK carries the buffer, the log-level filter and the OCSF logic. That means building and keeping six implementations in sync, and when the application crashes, the debug buffer dies with the process, which is exactly the moment we need it. On the right, option A, which we chose: the SDK stays thin and only configures and emits, using generated code rather than wrappers, as OpenTelemetry itself recommends. The agent on the node holds the buffer and the logic, written once in Go, and the buffer survives an application crash because it lives on the node's disk. One known gap: records still queued inside the SDK at the instant of a crash can be lost on the OTLP path; we flush on fatal errors and will measure the gap.
